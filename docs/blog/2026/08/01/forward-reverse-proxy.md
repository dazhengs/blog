# 最强正反向代理记忆法：代购 vs 10086 客服

和别人聊正向代理反向代理时，脑子总会思考一下，什么是正向代理什么是反向代理，如果搞混了，接下来的沟通就会出问题。

如果你也是正向反向分不清，接下来，我要让你瞬间记住且过目不忘。

首先记住，客户是上帝，我们是客户（端），正向还是反向也是站在我们客户端的角度出发的。

我们总是要找服务端请求服务。而现实情况由于种种原因，我们无法直接找到服务端，那么就需要中间人帮忙，这个中间人就是代理。

这个中间人如果是代替我去请求服务端，那么就是正向代理，英文名称叫 Forward Proxy。也就是朝向服务端方向，好理解吧。

同理，如果这个中间人是代替服务端去迎接客户端（我们）的请求，那么就是反向代理，英文名称叫 Reverse Proxy。

下面用生活中的例子更具体的描述一下：

**“代购”** 与 **“前台客服”**

一句话核心：**正向代理“替客户端办事”，反向代理“替服务端接客”。**

---

### 1. 正向代理 (Forward Proxy) = “找代购”

- **生活场景**：你想买海外某品牌的限量版球鞋，但你出不了国，或者该网站封锁了你的IP。于是，你找了一个**海外代购**帮忙买。
- **谁被隐藏了？**：你（客户端）被隐藏了。
- **上帝视角**：海外商家（服务器）只看到了代购在付钱拿货，商家**根本不知道你的存在**，他以为真正需要鞋的人就是那个代购。
- **技术映射**：当你在处理网络层的代理路由或开启 TUN 模式来实现某些特定流量转发时，就是在用正向代理。代理服务器代替你的电脑去向外网请求数据。
- **作用**：突破访问限制、隐藏真实客户端 IP。翻墙、绕过限制所使用的代理都是正向代理。

### 2. 反向代理 (Reverse Proxy) = “打 10086 客服”

- **生活场景**：你的手机停机了，你拨打 **10086**。电话接通后，为你办理业务的可能是 001 号接线员，也可能是 9527 号接线员。
- **谁被隐藏了？**：具体的接线员（服务端）被隐藏了。
- **上帝视角**：你（客户端）只知道自己打给了统一的“10086”（反向代理），你**根本不知道真正为你提供服务的是后台哪个具体的人**。所有的请求都由 10086 这个大门面接收，再由它在后台分配。
- **技术映射**：你平时配置和部署的 Nginx 经常就是扮演这个角色。客户端只访问 Nginx 的公网地址，Nginx 再把请求分发给背后机房里成百上千台真正的业务服务器。
- **作用**：负载均衡、隐藏真实服务器 IP、安全防护。

### Nginx 的正向代理配置示例

假设 A 服务器 (IP: 100.100.100.100) 需要去访问 B 服务器 (IP: 200.200.200.200)，但是由于某些原因无法直接访问，需要通过 C 服务器 (IP: 150.150.150.150) 作为代理。则 C 服务器的 Nginx 配置如下：

```nginx
server {
    listen 8080;
    location / {
        proxy_pass http://200.200.200.200;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

这里 C 就是代购，代替 A 访问 B。 意思就是 A 访问 C 的 8080，就相当于访问 B 的 80 端口一样。对 B 而言，仅仅知道 C 访问了自己，不知道 A 的存在。

比如生产环境仅有一台服务器 C 能访问企业微信机器人接口，那么另一台也需要往机器人发消息的话，就可以通过这台服务器 C，把 Nginx 作为正向代理，即可实现。

### Nginx 的反向代理配置示例

假设 A 服务器 (IP: 100.100.100.100) 是前台，B服务器 (IP: 200.200.200.200) 是后台。C 服务器作为反向代理，配置如下：

```nginx
server {
    listen 80;
    location / {
        proxy_pass http://200.200.200.200;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

这里 C 就是前台，代替 B 接收 A 的请求。 意思就是 A 访问 C 的 80，就相当于访问 B 的 80 端口一样。对 A 而言，仅仅知道 C 的存在，不知道 B 的存在。真实的服务器 B 被隐藏了。

比如生产环境 A 服务器是Nginx，后面有B、C、D三台服务器提供服务，Nginx 通过反向代理，可以把请求分发给B、C、D三台服务器，当B服务器坏了，Nginx 可以把请求分发给C、D服务器，从而实现负载均衡。

再仔细看上面的两个配置，会发现配置的形式并没有什么区别，仅仅是**代理谁**的区别。正向代理是代理客户端（自己），反向代理是代理服务端（后端）。

### 总结

- 正向代理（Forward Proxy）：正向代理是客户端替服务端办事，隐藏真实客户端。
- 反向代理（Reverse Proxy）：反向代理是服务端替客户端接客，隐藏真实服务端。
